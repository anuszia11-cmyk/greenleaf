# greenleaf
I tested /borrower/<id> while logged in as borrower 1 and changed the URL to /borrower/2. The server returned borrower 2's name, national ID and loan balance (HTTP 200), so this was an IDOR (OWASP A01, Broken Access Control). The app only checked that the user was logged in, not that the record was theirs. I fixed it by comparing the borrower ID stored in the signed session with the ID in the URL and returning 403 Forbidden when they differ, before the database is queried. Blocked attempts are logged for Task 5. I added four pytest cases (own record allowed, borrower 2 blocked with no data leak, IDs 2–10 blocked, logged-out user redirected), and they all pass. Evidence is in IDOR_report.md and the README is updated.
